# S1 - Admin Quản Lý Sự Kiện: Báo Cáo Cập Nhật Toàn Bộ

## ✅ TÓM TẮT NGẮN GỌN

Phiên bản hiện tại đã hoàn thiện hầu hết luồng quản lý event (BE + FE), xử lý banner S3, category CRUD, trang detail public, và luồng đăng ký/vé. Dưới đây là bản cập nhật chi tiết — kèm mô tả rõ ràng phần "Event" (những gì đã thực hiện), các file đã sửa và các bước tiếp theo.

---

## 📌 TRẠNG THÁI CHUNG

- Event CRUD + visibility: Đã hoàn thành
- Banner upload S3: Đã hoàn thành (presigned URL flow)
- Category CRUD (admin): Đã hoàn thành
- Event detail (public): Đã hoàn thành
- Đăng ký & vé (registration): Backend + Frontend đã tích hợp và cố định một số lỗi race-condition

## 🛠️ CHI TIẾT CÔNG VIỆC PHẦN EVENT (ĐÃ LÀM RÕ RÀNG)

1) Backend — Những thay đổi, lý do và điểm đáng chú ý
  - Tích hợp và củng cố logic ticket/registration:
    - Hợp nhất repository/service liên quan đến `Ticket` thành một đường dẫn duy nhất để tránh trùng lặp logic và model.
    - Các file chính đã sửa/đặt lại:
      - BE/src/Shared/Repositories/ITicketRepository.cs — chuyển sang DTO-based contract (GetEventByIdAsync, CreateTicketAsync, UpdateEventIncrementRegisteredCountAsync, GetTicketsByUserIdAsync, HasTicketForEventAsync).
      - BE/src/Shared/Repositories/Ticket/TicketRepository.cs — thực thi các phương thức DTO-based, mapping DynamoDB ↔ DTO.
      - BE/src/Shared/Services/Ticket/TicketService.cs — business logic đăng ký/vé dùng repository mới.
      - BE/src/Shared/Services/RegistrationService.cs — đồng bộ để dùng `CreateTicketAsync` & `GetTicketsByUserIdAsync` (thay vì model cũ), vẫn giữ rollback khi update RegisteredCount thất bại.

  - Cố định lỗi deserialization request body null:
    - Lambda handler đã được làm an toàn hơn, không deserialize khi body null/empty (đã phát hiện và sửa ở handler trước các thay đổi này).

  - Atomic increment / tránh overbooking:
    - Sử dụng DynamoDB conditional update (ConditionExpression) để tăng `RegisteredCount` chỉ khi nhỏ hơn `MaxSlots`.
    - Nếu condition fail → trả lỗi thích hợp (mapped lên 409 conflict trên FE) và rollback nếu cần.

  - Endpoints liên quan (đã có):
    - POST `/events/{eventId}/register` — luồng đăng ký (auth required)
    - GET `/my-tickets` — danh sách vé của user
    - GET/POST/PUT/DELETE các route quản trị event/category và presigned banner upload

2) Frontend — Những thay đổi, vị trí file và hành vi
  - Điểm chính: Bổ sung nút "Đăng ký nhanh" trên trang chi tiết sự kiện để gọi cùng API đăng ký đã có.
  - File đã sửa/đã cập nhật:
    - FE/src/components/events/EventDetail.tsx — thêm nút "Đăng ký nhanh" gọi `ticketService.registerTicket(eventId)`, xử lý trạng thái gửi, cập nhật view sau khi đăng ký thành công.
    - FE/src/components/registrations/RegistrationForm.tsx — form đăng ký chi tiết (đã tồn tại) vẫn được giữ làm đường fallback (hiển thị lỗi chi tiết, yêu cầu fullName/email).
    - FE/src/services/ticketService.ts — `registerTicket(eventId)` (POST `/events/{eventId}/register`) được sử dụng bởi MyTickets sandbox và nút nhanh.
    - FE/src/pages/user/MyTicketsPage.tsx — sandbox đăng ký test (input eventId), vẫn còn như công cụ test; file hiển thị danh sách vé live từ `/my-tickets`.
    - FE/src/components/registrations/RegistrationTable.tsx — component cũ không dùng đã được loại bỏ (thay bằng placeholder) để tránh nhầm lẫn.
    - FE/src/pages/admin/RegistrationManagementPage.tsx — cập nhật để không import component đã xóa và hiển thị placeholder/tin nhắn.

  - UX behavior:
    - Nếu user chưa login → nhắc chuyển sang `/login`.
    - Nếu event đã hết slot / không cho đăng ký → FE hiển thị thông báo; BE trả 409 khi atomic increment thất bại.

3) Kiểm tra/cleanup khác đã làm
  - Xóa file thử nghiệm không dùng: `FE/src/pages/public/EventTestPage.tsx`.
  - Dọn các implementation ticket trùng lặp, đồng bộ DTOs, mapper và services.

## GHI CHÚ / LƯU Ý KỸ THUẬT

- Registration race conditions được giảm thiểu bằng conditional update trên DynamoDB và kiểm tra duplicate trên tầng ứng dụng.
- Việc hợp nhất repository/service giúp tránh inconsistency khi thay đổi DTO hoặc mapper.
- Một số kiểm tra cuối (build toàn bộ solution) cần chạy trên máy dev vì shell environment trong workspace có hạn chế — mình đã thử chạy build ở phiên trước nhưng gặp parsing issues trong terminal của session; command đúng vẫn là `dotnet build BE\EventManagement.Serverless.sln`.
